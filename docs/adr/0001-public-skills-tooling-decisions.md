# ADR 0001: public skills tooling, cmux, graph, orchestrator, recall, and validator decisions

- Status: Accepted
- Date: 2026-11-21
- Extracted from: `skills/cmux/scripts/`, `skills/graph/scripts/`, `skills/orchestrator/scripts/`, `skills/recall/scripts/`, and `skills/skill-manager/scripts/`

## Context

Helper scripts across `cmux`, `graph`, `orchestrator`, `recall`, and `skill-manager` carried 293 lines of inline comments covering shell quoting traps, macOS coreutils differences, pixel-width typography guards, routing and benchmark parsing rules, and transcript filtering. Moving the genuine design constraints here keeps executable scripts clean under the comment ratchet without losing institutional memory.

## Decisions

1. **cmux workspace spawning and shell safety (`skills/cmux/scripts/spawn-workspace.sh`).** Parent-runtime detection prefers environment variables over the script path because `~/.codex/skills` and `~/.claude/skills` often symlink to the same checkout. Unknown leading arguments are checked before any cmux call so flags such as `--help` cannot spawn a workspace. `$MODEL` is single-quoted so zsh does not treat 1M-context identifiers containing brackets as globs. Prompts travel via a temporary file so leading `---`, backticks, or unmatched quotes stay intact. `CMUX_QUIET=1` and pattern extraction guard against deprecation notices printed on `2>&1` breaking positional `awk`. `--worktree` gives concurrent repo writers isolated working trees so one session's `git checkout` cannot overwrite another's files. Multi-line YAML goals in session notes use literal block scalars (`|`) because Obsidian's Properties parser breaks on multi-line double-quoted scalars.
2. **cmux workspace closing and macOS `grep` (`skills/cmux/scripts/close-workspace.sh`).** cmux reuses workspace numbers, so matching `workspace_id` alone hits historical closed notes. Only open notes whose frontmatter matches the current live workspace name are flipped to `done`. The file loop uses `grep -l --null` rather than `grep -lZ` because macOS `grep -Z` means `--decompress` and emits newline-separated paths that break `read -d ''`.
3. **Pixel-width node text guard and content-hash staleness (`skills/graph/scripts/render-graph.py`, `selftest.py`).** A shared character budget allowed 12px monospace `.nsub` lines (7.225px per glyph in Menlo) to overflow 246px boxes calibrated for 11.5px proportional `.nown` text. Separate per-character advance tables for regular and semibold weights predict rendered widths within 1.7px using an 8px `MARGIN_PX` floor, while unknown glyphs assume a wide advance so the guard fails safe. Opt-in `meta.maxlen` remains a hard failure whereas the pixel guard warns by default unless `width_check` is set to `break`. Staleness checks hash file contents rather than mtime so `git checkout` does not trigger false stale states. The selftest matches SVG node groups rather than the bare `.s-stale` class string because `.s-stale` always appears in the page stylesheet. New nodes are logged as first seen rather than added so backfills do not misdate existing graphs, and stages with a leading middle dot render dashed aside buses.
4. **Orchestrator benchmark scaling and timezone fallback (`skills/orchestrator/scripts/aa_refresh.py`, `resolve.py`).** Index fields are scaled 0 to 100 while individual benchmarks such as `terminalBench40` are 0 to 1 and scaled to points. The base record represents the top effort tier and non-reasoning records are dropped. When `zoneinfo` lacks a requested timezone, `resolve.py` falls back to a fixed UTC+8 offset.
5. **Recall transcript floors and noise filtering (`skills/recall/scripts/recall-day.py`, `session-graph.py`).** Codex transcripts are included alongside Claude transcripts unless suppressed or filtered with `--project`. Because Codex message counts reflect human turns directly rather than Claude's higher event count, Codex sessions use a minimum floor of 1 turn instead of Claude's `min-msgs` threshold. Files referenced by more than 60% of sessions are filtered out of the session graph as ambient noise.
6. **Pure-Bash skill validation and intake panel rules (`skills/skill-manager/scripts/validate.sh`).** `validate.sh` stays in pure Bash so it runs on minimal hosts where only coreutils are guaranteed. Intake panel validation enforces at most four questions (excluding questions carrying `slot of:`), two to four options each, and `label - description` option separators.
